# CyberOTP Studio — RFC 6238 기반 모바일 OTP 웹앱 (`26-w11-mobile-otp`)

> **CyberOTP Studio**는 인터넷 통신 없이도 브라우저 내부에서 안전하게 동작하는 **RFC 6238 / RFC 4226 표준 기반 모바일 OTP (TOTP 2단계 인증) 웹 스튜디오**입니다.  
> 스마트폰의 Google Authenticator, Microsoft Authenticator 앱과 실시간으로 정확히 동일한 6자리 인증 번호를 생성하고 검증할 수 있는 통합 대시보드를 제공합니다.

---

## 🌟 소개

**CyberOTP Studio**는 단일 화면 2단 인터랙티브 대시보드로 설계되었습니다:

- **좌측 [서비스 서버 시뮬레이터 (2FA Enrollment Server)]**:
  - 발급자(Issuer: 기본값 `KOPO-CyberSec`) 및 사용자 계정(Account: 기본값 `student@kopo.ac.kr`) 설정
  - 암호학적 난수 기반 Base32 비밀 키(Secret Key) 생성 및 원클릭 복사
  - Google Authenticator 표준 규격(`otpauth://totp/...`) QR 코드 실시간 생성 및 스마트폰 앱 연동
  - 스마트폰 분실에 대비한 **비상 1회용 백업 복구 코드 (Emergency Backup Codes)** 5개 발급 관리

- **우측 [모바일 인증기 & 코드 검증기 (Authenticator & Verifier)]**:
  - 30초 카운트다운 게이지 프로그레스 바 및 잔여 시간(1~30초) 실시간 시각화 (시간 경과에 따른 색상 전환 경고)
  - 스마트폰 앱과 1:1로 일치하는 실시간 6자리 OTP 표시 및 원클릭 복사 / 자동 채우기
  - 사용자 입력 6자리 코드 검증 및 성공/실패 명확한 배지 판정
  - 시계 오차 보정용 **±30초 시간 오차(Drift Skew) 허용 토글**
  - 최근 인증 시도 이력 감사 로그(Audit Logs) 실시간 기록

## 🤖 나의 AI 기획·구현 과정

### 1. AI 협업 방식
- **Gemini 3.8 Flash & Antigravity IDE 활용**:
  - 프로젝트 시작 전 RFC 6238(TOTP), RFC 4226(HOTP), RFC 4648(Base32) 표준 규격의 핵심 수식을 정리하고, 서비스 서버와 모바일 인증기를 한눈에 비교·체험할 수 있는 2단 스튜디오 대시보드를 기획했습니다.
  - 암호화 로직을 UI와 완전히 격리하기 위해 `src/utils/totp.js` 모듈을 독립 설계하고, RFC 6238 Appendix B 공식 테스트 벡터 5종을 대상으로 단위 테스트를 먼저 수행한 뒤 React UI 컴포넌트를 구현했습니다.

### 2. 구상한 화면 및 사용자 흐름
1. **최초 진입**: 페이지 접속 즉시 안전한 Base32 비밀 키(20바이트/160비트 엔트로피)와 QR 코드가 로컬에서 자동 생성됩니다.
2. **스마트폰 연동**: 스마트폰에서 Google Authenticator 또는 Microsoft Authenticator 앱을 켜고 좌측 QR 코드를 스캔합니다.
3. **실시간 비교**: 스마트폰에 표시되는 6자리 숫자와 우측 웹 화면의 "현재 30초 주기 예상 OTP"가 매 30초마다 동시에 정확히 일치하여 바뀌는 것을 확인합니다.
4. **검증 체험**: 스마트폰의 6자리 코드를 입력하고 `[인증 확인]`을 누르면 서버가 즉시 유효성을 검증하여 초록색 "인증 성공 (Verified)" 배지를 띄웁니다.
5. **비상 백업**: 폰이 없는 긴급 상황을 시뮬레이션하여 백업 복구 코드로도 인증을 수행해보고 사용된 코드가 소멸되는 흐름을 체험합니다.

### 3. 구현 중 맞닥뜨린 문제와 해결 과정
- **RFC 6238 공식 테스트 벡터 일치 검증**:
  - TOTP는 8바이트 Big-Endian 시간 카운터 버퍼(`DataView.setBigUint64`)를 정확히 구성해야 공식 표준과 일치합니다.
  - RFC 6238 Appendix B의 SHA-1 공식 테스트 벡터(Time=59초 ➔ 287082, Time=1111111109초 ➔ 081804, Time=1234567890초 ➔ 005924, Time=2000000000초 ➔ 279037 등)를 테스트 스크립트로 실행하여 **100% 통과**함을 사전에 엄격히 검증했습니다.
- **Base32 인코딩/디코딩 엔트로피 일치**:
  - HMAC-SHA1의 권장 키 길이인 160비트(20바이트)는 5비트씩 묶을 때 정확히 32개의 Base32 문자로 나누어 떨어지므로 패딩(`=`) 오류 없이 완벽하게 스마트폰 앱과 상호 운용되도록 구현했습니다.
- **React 컴파일러 린트 경고 해결**:
  - `oxlint` 실행 시 발생한 `set-state-in-effect` 경고를 방지하기 위해 초기 비밀 키 생성을 `useState`의 지연 초기화 함수(`() => generateSecret(20)`)로 리팩터링하여 0 warnings, 0 errors를 달성했습니다.

## 🛡️ TOTP 원리 및 보안 점검 (사이버보안과 체크포인트)

### 1. `Math.random()` 대신 `window.crypto.getRandomValues()`를 사용하는 이유
- `Math.random()`은 암호학적으로 안전하지 않은 의사난수 생성기(PRNG, 주로 xorshift128+ 등)를 사용합니다. 내부 시드와 직전 출력값 몇 개만 알면 다음 생성될 난수를 수학적으로 역추적할 수 있어, 2단계 인증의 핵심인 비밀 키(Secret)를 공격자가 쉽게 탈취·추측할 수 있습니다.
- 반면 `window.crypto.getRandomValues()`는 운영체제(OS)의 하드웨어 인터럽트, 키보드/마우스 입력 타이밍 등 물리적 시스템 엔트로피 풀을 수집하는 **CSPRNG (Cryptographically Secure Pseudo-Random Number Generator)**를 사용하므로 난수 예측이 불가능합니다.

### 2. Zero-Transmission (무전송 원칙)과 Web Crypto API
- 본 프로젝트는 비밀 키 생성 및 HMAC-SHA1 암호화 연산 과정에서 일체의 외부 API 호출을 수행하지 않습니다.
- 모든 암호 연산은 브라우저 내장 하드웨어 가속 API인 `window.crypto.subtle` (`importKey`, `sign`)을 통해 **클라이언트 메모리 내부에서만 수행**됩니다.
- **개발자 도구 (F12) Network 탭 점검 결과**:
  - 초기 정적 파일(HTML, JS, CSS) 로드 이후, 비밀 키 재발급, QR 갱신, OTP 번호 계산, 검증 버튼 클릭 시에도 **외부 네트워크 통신(XHR/Fetch)이 0건**임을 확인했습니다.
  - 서버나 제3자 네트워크로 비밀 키가 전송되지 않으므로 네트워크 스니핑, 중간자 공격(MITM), 서버 유출 위협으로부터 안전합니다.

### 3. 스마트폰 Authenticator 앱과의 실시간 일치 검증
- Google Authenticator 앱으로 웹의 QR 코드를 스캔한 후 실시간 테스트를 진행했습니다.
- 스마트폰 앱에 나타나는 6자리 숫자와 웹 화면 우측에 표시되는 예상 OTP 번호가 **매 30초마다 1초의 오차도 없이 동일하게 변경**되는 것을 확인했습니다.

## 🚀 나만의 확장 기능

1. **비상 1회용 백업 복구 코드 (Emergency Backup Codes) 시스템**:
   - `crypto.getRandomValues()`를 이용해 5개의 고유한 8자리 복구 코드(`XXXX-XXXX`)를 발급합니다.
   - 스마트폰을 사용할 수 없는 비상 상황 시 탭 전환을 통해 백업 코드로 즉시 인증할 수 있으며, 한 번 사용된 코드는 즉시 소멸(무효화)되어 재사용 공격을 방지합니다.
2. **시간 오차(±30초 Drift Skew) 허용 옵션 토글**:
   - RFC 6238 권장 사항에 따라 클라이언트 디바이스와 서버 간 시계가 어긋날 수 있는 상황을 고려하여 $T-1, T, T+1$ 주기를 허용하는 시간 오차 보정 옵션을 제공합니다.
3. **실시간 인증 시도 감사 로그 (Audit Logs)**:
   - 사용자가 입력한 인증 코드의 검증 결과(성공/실패 여부, 시각, 인증 유형, 판정 메시지)를 실시간 감사 로그 카드로 기록하여 보안 모니터링을 지원합니다.
4. **편의 UX 기능**:
   - Base32 시크릿, 현재 OTP, otpauth URI 원클릭 클립보드 복사
   - 테스트를 빠르게 수행할 수 있는 "입력창 채우기(Auto-fill)" 기능
